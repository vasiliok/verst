# src - the shared C++ core

[verst](../README.md) > src

Everything the desktop tools and the iOS app share. One directory per part; each has
its own README.

| Directory | What it holds |
|---|---|
| [base](base/README.md) | scalar types, memory-mapped files, string pool, pipeline progress |
| [geometry](geometry/README.md) | coordinates (degrees, Web Mercator), plane geometry, region outlines |
| [storage](storage/README.md) | the nav file format and the tiled map (data side, never seen by clients) |
| [provider](provider/README.md) | the client API `Vrst_map_provider` and its types, and the nav-file implementation |
| [route](route/README.md) | the router: car, bike and foot routes and the way back |
| [search](search/README.md) | offline address search (engine behind an interface, SQLite FTS5 today) and map links |
| [session](session/README.md) | session logs, test scenarios, activity recording, GPX tracks |
| [render](render/README.md) | the OpenGL renderer (GL 3.3 desktop, GLES 3.0 iOS) |
| [convert](convert/README.md) | OSM extract -> nav files (merge, roads, layers, addresses) |
| [tools](tools/README.md) | command-line programs (osm2nav, pbf_merge, navcheck, navroute, navsearch, navview) |

## Includes

Includes are relative to `src/` and name the directory:

```cpp
#include "route/router.h"
#include "geometry/geo.h"
```

`vrst_types.h` is generated by CMake into `<build>/generated/` and included without a
directory.

## Who uses what

```
base, geometry           <- used by everything
provider (client types)  <- map_provider.h, map_scene.h, route_result.h, search_result.h
storage, route, search   <- the data side; use base, geometry and the client types
provider (nav_map_provider) <- built on storage, route and search
render, session          <- use the client API only (provider), never storage files
convert                  <- base, geometry, storage format, search engine writer
tools, ios               <- any of the above
```

Clients (render, session, the iOS app, navview) see only `Vrst_map_provider`: opaque
keys, degrees, status and events; no files, formats, grid or threads.

## Libraries (CMakeLists.txt)

- `vrst_core`: base, geometry, storage, provider, route, search, session.
- `vrst_render`: render (when OpenGL is available).
- `vrst_convert`: convert.
- one executable per file in tools.
